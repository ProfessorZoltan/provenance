# Provenance — Art-to-design guide

Source: [Game Design Doc v0.1](GAME_DESIGN_v0.1.md), supplied September 18, 2026. Art revision 02: locations prioritise recognisable architecture and objects over the earlier strict pixel constraint, and altered histories change the actual structures of a place; characters and enemies keep the FF1-inspired coarse pixel direction. These are original assets, not copies of Final Fantasy artwork.

The library contains **151 catalog entries** and **637 standalone SVG files**. Open [the visual catalog](../public/art/index.html) to inspect every asset, pose and layer. Machine-readable inventory: [catalog.json](../public/art/catalog.json).

## Art direction and implementation contract

- Scenes are illustrated, not gridded: Deep Sites 640 × 360, Waypoints 480 × 270, endings 640 × 360, all 16:9; scale them smoothly. Sprites stay on the pixel grid: battle cells 32 × 48, portraits 32 × 32, map tokens 16 × 24. Scale sprites by whole-number factors where practical with `image-rendering: pixelated`.
- Palettes retain the guide’s era identity: warm founding, navy/gold handover, moss/rust quiet, cyan future. Future scenes retain white/cyan architecture against dark blue command panels for legibility.
- Party sprites face left for heroes on the right; enemy sprites face right. Party Echo variants retain left-facing source art; mirror them when used as enemies. SVG files are static pose assets; animate by swapping poses or sheets. Do not interpolate or blur pixel edges.
- Scene files are standalone. Where present, `sky`, `distant`, `midground`, `foreground` compose in that order. `hub` is the complete scene; `battle` is a separate scene composed to leave space for horizontal combat. Never put the full hub beneath all its layers.
- Stable IDs and file roles are in the manifest. Never infer story logic from a filename; map canonical game flags to a variant explicitly. `proposed: true` records inferred art choices, not additions to the narrative canon.
- Most scenes and characters are prepared assets for future development. This does not implement the guide’s unreleased locations, party recruitment, combat abilities or endings.

## Coverage and decisions

- All eight named party members receive battle poses, dialogue portraits and map tokens. Other-era Echo assets are visual interpretations; the guide does not specify complete biographies or outfits in each era.
- All five Deep Sites × four eras receive hub and battle art, plus scene layers and map icons.
- All twenty explicitly named Waypoints receive art. The guide says “6–8” Waypoints per era but names five per era; no additional places are invented to fill that discrepancy.
- Ripple states, the stacked Meridian dungeon, enemy families, boss forms, named slice NPCs, world-map art, ending illustrations and common HUD pictograms support likely follow-on work.
- Geography, exact appearances, unspecified enemy loadouts and ending compositions are art proposals. Narrative conditions remain those in the original guide.
- Settlements and faction hubs do not gain random encounters merely because artwork exists. Battle art is supplied where relevant to Deep Sites, ruins or wilds.
- These are static game-ready assets and pose sets, not a complete animated cinematic or modular animation engine. Existing CSS supplies ambient motion; reduced-motion must retain readable static states.

## Using this library in Claude Code or another editor

1. Read this guide and `docs/GAME_DESIGN_v0.1.md` before adding content.
2. Open `public/art/index.html` or `/art/` on the deployed site; search the catalog by name, era or role. `npm run art:export` writes `art-directory.html`, the same page with every SVG inlined, for reading offline or on a phone.
3. Use `public/art/catalog.json` as the complete inventory. All `files` values are relative to `public/art/`. `src/art/catalog.json` is the bundled runtime subset.
4. Use `artAssetUrl(id, role)` and `librarySvg(id, role)` from `src/art/library.ts` to render by stable ID. Do not copy pixel data into game logic.
5. Add gameplay content separately in the existing JSON schemas. An art entry alone is not an unlock or encounter.
6. The location, character, enemy, Echo and ending SVGs are authored output from art revision 02 and are newer than the generators under `scripts/art-*.mjs`. Do not run `npm run art:build`: it would regenerate the earlier library over them. Regenerate only the inventory with `node scripts/art-catalog.mjs` after editing a manifest.
7. Run `npm run art:check`, `npm run build`, and `npm test`. In this Windows sandbox use `-- --configLoader runner` for Vite/Vitest if their default config bundler cannot inspect a parent directory.

## Runtime integration

The current Kell slice uses the library through the existing rig/background wrappers. Existing character IDs, dialogue IDs and game logic stay compatible. Named NPC portraits replace stand-in party portraits. Background variants are selected explicitly from timeline flags. See `src/art/library.ts`, `src/art/rigs.ts`, `src/art/pixel-backgrounds.ts`, and `src/ui/screens/dialogue.ts`.

## Copyable integration examples

```ts
import { librarySvg, artAssetUrl } from './art/library';
const hero = librarySvg('mara', 'idle', '0 0 32 40');
const portrait = librarySvg('mara', 'portrait', '0 0 32 32', 'portrait-svg');
const battleBackground = artAssetUrl('2064_halden', 'battle');
const echo = librarySvg('mara_echo_2148', 'act', '0 0 32 40');
```

A new location can point its existing `background.layers[].art` field to catalog IDs and roles:

```json
{ "layers": [
  { "id": "sky", "drift": 0.1, "art": "2064_halden:sky" },
  { "id": "distant", "drift": 0.3, "art": "2064_halden:distant" },
  { "id": "midground", "drift": 0.6, "art": "2064_halden:midground" },
  { "id": "foreground", "drift": 1.0, "art": "2064_halden:foreground" }
], "particles": "glint" }
```

For automatic composed battle backgrounds, map a new gameplay location ID to its catalog scene ID in `sceneAssetId`. The catalog is intentionally separate from gameplay IDs. File palettes are explicit and do not inherit CSS variables; edit generator palettes to change an outfit. Future 2312 alterations can combine prepared ripple scenes with a chosen era palette, but arbitrary mixed-timeline rendering remains future engine work.

## Known limits

- No bitmap/raster exports are required; SVGs remain editable and portable.
- World maps are art compositions with proposed coordinates, not authoritative collision or navigation data.
- New NPC archetypes are explicitly proposals. Do not assign them story roles without a game-design decision.
- Pose art is provided for presentation; the battle engine still controls action timing, damage, turn order and targeting.
- No original Final Fantasy game assets were used. The influence is low-resolution pixel composition and the horizontal battle convention.
